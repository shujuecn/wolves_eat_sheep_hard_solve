# 狼羊棋 · 网页版（人机对战）

5×5 人机对战的浏览器版本：**左侧棋盘 + 右侧对局信息**，点选走棋、快捷键操作。
棋盘与棋子全部用 CSS 绘制（圆形棋子：粗楷「狼」红字 /「羊」黑字），**不加载任何图片素材**；
棋盘元素只建一次、走棋后按格原地增量更新，不做整盘重绘，操作流畅不闪烁。

> 📖 **Web 使用说明**（启动 / 界面 / 模式 / 最优解 / 棋谱导出 / 常见问题）：
> 见 [web/USAGE.md](USAGE.md)。

## 引擎：纯硬解表库（无神经网络）

- 全部走子决策都来自**逆向分析硬解表库**：k=4…15 已全部解出，开局羊数 15 ≤ 15，
  整局都在表库覆盖范围内 → 模型每一手都是**双方最优前提下的表库最优解**。
- 表库文件：`data/ws_tb_dtc_260819/dtc_k*.bin`（mmap 只读加载，启动即用）。
- 启动时自动扫描表库目录，取"已截完"（magic=WSTB 且 completed=1、尺寸正确）的
  最大 k 作为覆盖分界；表库后续扩充后重启即自动生效。
- **节奏**：你走完一步后，模型**隔 1 秒**再应手（期间显示“模型思考中”）。

## 运行（SSH 开发场景，端口转发玩）

```bash
cd <仓库目录>
python3 web/server.py --port 8080        # 仅监听 127.0.0.1
```

本机浏览器访问（端口转发）：

```bash
ssh -L 8080:127.0.0.1:8080 <用户>@<服务器>
# 打开 http://127.0.0.1:8080
```

## 界面与操作

- 开局先点「狼 / 羊」选择阵营。
- **左列**：棋盘（翻转视角即你执狼时狼在最上排）、状态行、悔棋/换边/重开按钮。
- **右列**：
  - **局面分析**：当前回合一方的**全部**候选最优续着（表库结论，如 `狼胜·最快9步`，
    按有利程度与最快步数排序，不再截断前 10 条；列表过长时可滚动）。顶部是整局最优解。
  - **对局记录**：玩家/模型每一步的走子（含吃子）与走完后局面的结论。
- 走棋：点自己的棋子 → 落点绿色高亮 → 再点落点；也可以**直接点右侧候选框的某条
  最优解**走棋 —— 轮到玩家时走玩家自己的子，轮到模型时替模型走棋（两种模式下均可用）。
- 快捷键：`u` 悔棋 · `s` 换边 · `r` 重开。
- **自动/手动模式**：按钮切换。自动（默认）→ 模型隔 1 秒自动应手；
  手动 → 模型不自动走。**两种模式**下点右侧候选最优解即可走棋：
  轮到模型 → 直接替模型走（自动模式下点选即覆盖本次自动应手；不点则模型照常自动走）；
  轮到玩家 → 走玩家自己的子；
  手动模式下还可以**直接在棋盘上点选模型方的棋子**替它走棋。
- **对局记录标记**：模型方每步带来源标记 —— `最优解`（模型自动应手，或玩家代走
  且落在当前局面的最优解档，按最优解标记）／`玩家自选`（玩家代走但非最优解档）。
- 鼠标悬浮候选框某条最优解时，棋盘就地预览这步棋：金色虚线环=待移动的子、
  绿色落点=目的地、红色高亮=可被吃掉的子；均为静态简单标记，不打断操作。
- **模型选步**：只在表库最优档选步（必胜最快/必败拖延/和棋），同档内优先选
  不会回到已出现局面的走法（防来回走触发 5 次重复判和），其余等价走法随机挑选。
- **无尽模式**：棋盘下方勾选框，解除 150 步上限——超过 150 步继续对局，
  最优解提示与对局记录照常保留（表库结论只依赖局面，与步数无关）；
  若已因 150 步判和，勾选后会自动解除终局继续下。
- **自由移动（摆子）模式**：无尽模式右侧勾选框，专为**快速调整到想要的残局**：
  狼可跳到任意位置（或直接跳到任意羊格吃掉该羊）、羊可移动到任意空地，双方棋子
  都可直接点选、无步数限制。勾选时**自动切换为手动模式且期间无法切回自动**（切回
  按钮置灰 + 服务端拒绝）；关闭后**保持手动模式**，可自行切回自动。开启期间
  **不提供最优解更新**（表库按标准规则求解，不适用该变体），模型也不自动应手；
  关闭后立即按当前局面恢复标准规则与最优解提示。自由移动期间的对局记录以
  `自由移动` 标记，恢复后继续按表库给出结论。
- **一键导出最优棋谱（最优解功能区右上角「导出最优棋谱」按钮）**：点击后弹出简洁
  配置页：**先走方固定=当前轮到方（视角随 Web 端，不可切换）**，可选**目标
  （狼胜/羊胜/和棋，随先走方自动约束）**、**导出条数（1～10，默认 1）**、
  **步数起点（从当前步数计/从 1 计）** 与 **最大步数（150 默认 / 160）**，
  点击「确认」后才开始分析。计算在服务端**后台线程**执行，加载界面实时显示
  **进度条 + 百分比 + 耗时（秒，2 位小数）**；期间对局暂停、界面锁定、禁止任何操作
  （服务端同步加锁，其它指令一律拒绝）。**超过设定最大步数的最优解不进棋谱**（只
  过滤，PNG 仅标注实际总步数）；目标与当前视角的表库最优结局不符时，给出可直接改选
  的提示（如「目标『狼胜』不可达成，可改选『和棋』」；视角已必败则提示「当前视角已
  必败，无法生成最优棋谱」）。导出**完全只读、不改动当前局面**。棋谱**不假设对手
  犯错**：对手每步都走表库最强防守（最长拖延、绝不送分），因此导出的胜线是官方规则
  下可合法完成的**最长强制线**，全程需步步精确；每条棋谱按 **5 列多行**棋盘子图
  排版（PNG 头部仅一行「目标 · 全程实际总步数 · 先走方」），子图只含棋盘元素，
  高亮金=待走子、绿=落点、红=被吃子，导出为**高清大尺寸 PNG**。关闭预览后自动恢复
  对局。
- **自动存档**：每次对局结束或手动重开，对局记录自动保存为
  `data/saved_games/game_YYYYMMDD_HHMMSS_*.json`（每步走子/吃子/表库结论 + 终局 FEN），
  记录面板实时显示“已自动保存 N 局”。
- 错误提示会显示在棋盘下方，并自动与服务端重新同步局面。

## 依赖

- Python 3.10+，**纯标准库**（HTTP 服务 + mmap），无第三方包、无 torch。
- 表库文件：已解表库共约 18 GB，默认从 `data/ws_tb_dtc_260819/` 读取
  （`--data-dir` 可覆盖）；全新克隆后需自行补充（重新求解或拷贝）。
